# Internationalisation

Stable ids everywhere: `ui.close`, `menu.file`, `prefs.theme`, `cmd.shell.preferences`, `panel.configure`,
`tab.home`, `home.new`, `ui.browser_title`, `ui.history_title`, `ui.colour_vision_off`.
`assets/locales/en.json` is the source of truth (`id → text`); `es.json` must have exactly the same
keys.

Catalogues that group by number use the `_one` / `_other` suffix and `{count}`:
`ui.browser_count_one` (`{count} body`) and `ui.browser_count_other` (`{count} bodies`), formatted
with `i18n::format(id, &[("count", "2")])`.

- `tr("ui.close")` — fixed UI string; returns the active language, then English, then the id.
- `format("about.version", &[("version", "3")])` — `{version}` placeholders; unknown placeholders stay
  visible.
- `tr_label(text)` — for labels carried by data or generated tables; a known English text is
  translated, anything else passes through.
- `tr_name(text)` — a name a person typed, never translated.
- `tr_dyn(text)` — translate when a key or known English text is found, otherwise return the text
  as-is (data-driven labels).
- `i18n::scope(language)` — the shell enters it once per frame; `language()` reads it back.

Command labels (`cmd.*`), panel labels, tab labels, menu titles and preference page labels are ids
resolved through the catalogue; an app never stores displayed text in `CommandSpec`/`TabSpec`.

`LOCALES` lists the catalogues (`en`, `es`); `COMPLETE` lists the languages the gate requires to be
complete. Add a language by adding its JSON, a `Catalog` static, its entry in `LOCALES` and, once
translated, `COMPLETE`.

`cargo xtask i18n --check` fails when a complete language misses an English key, a language has keys
English lacks, or code uses a literal `tr("…")` / `format("…")` id that English does not define.
